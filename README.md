# 밤티 (Bamti)

**이 페이지, AI가 만든 티 납니까?**
브라우저 익스텐션이 페이지의 UI 지문을 스캔해 무엇이 "생성 도구 기본값"인지 짚고 개선 방향을 제안합니다.

밤티는 **"AI가 썼다"고 단정하지 않습니다.** 발견된 지문의 개수와 그 근거만 보여줍니다.

---

## 현재 상태 — Phase 1 (로컬 규칙 엔진)

LLM·네트워크·계정 없이 완전히 로컬에서 동작합니다. 페이지 내용은 브라우저 밖으로 나가지 않습니다.

### 설치

```bash
open -a "Google Chrome" chrome://extensions
```

우측 상단 **개발자 모드** 켜기 → **압축해제된 확장 프로그램을 로드** → 이 폴더 선택.
아무 페이지에서 툴바 아이콘 클릭, 또는 단축키 **control+Shift+B** (Mac) / **Alt+Shift+B** (Windows·Linux).

> Cmd+Shift+B / Ctrl+Shift+B 는 크롬의 **북마크바 토글**이라 익스텐션이 받을 수 없습니다.
> 단축키가 안 먹으면 `chrome://extensions/shortcuts` 에서 직접 지정하세요.

### 스캔 가능한 대상

| 대상 | 상태 |
|---|---|
| `https://` · `http://` (localhost 포함) | 바로 됨 |
| `file://` 로컬 HTML | 크롬 설정 1회 필요 — 아래 참고 |
| `chrome://` · 웹스토어 · `about:` | 불가. 크롬이 모든 확장 프로그램의 접근을 막습니다 |

**로컬 HTML 파일 스캔하기:** 크롬은 확장 프로그램의 로컬 파일 접근을 기본 차단합니다.
`chrome://extensions` → 밤티 → **세부정보** → **"파일 URL에 대한 액세스 허용"** 을 켜세요. 한 번만 켜면 됩니다.
토글이 꺼진 상태로 `file://` 페이지를 스캔하면 패널이 이를 감지해 **설정을 바로 여는 버튼**을 보여줍니다.

### 패널은 탭을 따라다닙니다

패널은 **창 단위**로 열립니다. 탭을 바꾸거나 새 탭을 열어도 패널은 남고, 활성 탭을 따라가며 자동으로 스캔합니다.
(탭 전용으로 열면 새 탭에서 패널이 사라지고 아이콘을 다시 눌러야 합니다 — 초기 버전의 문제였습니다.)

권한이 없는 탭에서는 아이콘으로 한 번 스캔하는 방법과 **이 사이트 항상 허용** 버튼을 보여줍니다.
현재 사이트에 대해서만 권한을 요청하며, 허용하면 바로 스캔합니다. 거절해도 권한창을 반복해서 띄우지 않습니다.

새 탭 페이지 같은 크롬 내부 페이지에서는 에러 대신 조용한 대기 상태를 보여주고, 페이지를 열면 자동으로 스캔합니다.

### 페이지가 바뀌면 자동으로 다시 스캔합니다

패널은 활성 탭을 추적합니다. 그 탭이 새로고침되거나 다른 페이지로 이동하면
즉시 **"페이지가 바뀌었습니다"** 배너를 띄우고 이전 결과를 흐리게 만든 뒤, 로드가 끝나면 자동으로 다시 스캔합니다.
HTML을 고치고 새로고침하면 패널이 따라옵니다.

리포트 상단에 **어느 페이지를 몇 시 몇 분 몇 초에 스캔했는지**가 항상 표시됩니다. 낡은 결과인지 여기서 확인하세요.

**탭이 다른 출처로 이동하면** 크롬이 `activeTab` 권한을 끊기 때문에 자동 재스캔이 실패합니다.
이때 패널은 옛 결과를 지우고 "아이콘을 다시 눌러라"고 안내합니다. 옛 결과가 남아 있는 일은 없습니다.

**↻ 다시 스캔** 버튼은 패널이 속한 창에서 **지금 보고 있는 탭**을 스캔합니다.
빠른 탭 전환이나 페이지 이동 중 도착한 이전 결과는 버립니다. 갱신 중에는 옛 결과의 복사·위치 표시를 비활성화합니다.

### 결과에서 개선 방향까지

- 이름과 발견 개수가 보이는 **카테고리 버튼**으로 결과를 좁히고, 항목·근거·개선 방향을 **검색**합니다.
- **모두 펼치기**로 개선 방향을 한 번에 읽습니다. 취향 항목은 기본적으로 접혀 있고 점수에서 제외됩니다.
- 개별 **개선 제안 복사** 또는 **전체 제안 복사**로 근거와 개선 방향을 편집기·AI 채팅에 붙여넣습니다.
  전체 복사는 검색 조건과 관계없이 해당 리포트 전체를 복사합니다. 자동 복사가 차단되면 직접 선택할 텍스트를 제공합니다.
- **이 항목만 N곳 표시**로 위치를 확인합니다. 전체 표시가 꺼져 있을 때 선택 표시를 해제하면 원래의 꺼진 상태로 돌아옵니다.
- 점수 옆에서 **AI 생성 확률이 아니라 패턴 점수**임을 설명하고, 일부 요소·규칙이 누락된 검사는 안내문을 표시합니다.
- 오류 화면의 **다시 시도**, 파일 접근 설정, 하단 **도움말·진단 정보 → 단축키 설정**으로 복구할 수 있습니다.

### "항상 허용" — 클릭 없이 계속 스캔하기

기본 권한은 `activeTab` 이라 **아이콘을 누른 그 탭, 그 출처**에서만 유효하고, 탭이 다른 출처로 이동하면 끊깁니다.
설치 시 "모든 사이트 데이터를 읽습니다" 경고를 피하려는 선택인데, 매일 쓰는 개발 서버에서는 번거롭습니다.

그래서 리포트 상단에 **항상 허용** 버튼이 있습니다. 누르면 그 출처에 대한 영구 권한을 요청합니다 (크롬 확인창 1회).
허용된 출처에서는 페이지를 옮기거나 새로고침해도 아이콘 클릭 없이 자동 재스캔이 이어집니다.

- 포트는 무시합니다. `localhost` 를 한 번 허용하면 `:3000` `:5173` `:8777` 전부 커버됩니다.
- `file://` 은 전체(`file:///*`)로 허용됩니다. 파일 URL 액세스 토글은 별도로 켜야 합니다.
- 다시 누르면 해제됩니다. `chrome://extensions` → 밤티 → 세부정보 → 사이트 액세스에서도 볼 수 있습니다.
- 매니페스트의 `optional_host_permissions` 로 선언되어 있어 **설치 시 경고는 그대로 없습니다.**

### 개발 중 주의 — 확장 프로그램 자체의 캐시

- `src/` 를 고친 뒤에는 `chrome://extensions` 에서 밤티 카드의 ↻ 를 눌러야 반영됩니다.
- **이미 열려 있는 사이드패널은 옛 `panel.js` 를 계속 씁니다.** 확장 프로그램을 다시 로드한 뒤 패널을 닫고 다시 여세요.
- 페이지에 주입되는 `signals.js` 는 스캔마다 새로 주입되므로, 확장 프로그램만 다시 로드하면 새 규칙이 바로 적용됩니다.

### 권한 설계

`activeTab` + `scripting`만 씁니다. `<all_urls>` 호스트 권한을 요청하지 않기 때문에
설치 시 "모든 사이트의 데이터를 읽습니다" 경고가 뜨지 않습니다.
처음에는 사용자가 단축키나 아이콘을 눌러 접근을 허용한 탭을 스캔합니다.
패널이 열려 있는 동안에는 접근 권한이 있는 활성 탭의 이동·새로고침에 맞춰 재스캔합니다.
**이 사이트 항상 허용**은 선택한 출처에 대한 추가 권한이며, 설정한 출처에서만 지속됩니다.

`src/core/signals.js` 가 이 프로젝트의 전부입니다. 나머지는 배관입니다.

죽은 링크 12개와 검색결과에 노출되는 `<title>`은 반박이 안 됩니다.

### 지문 위치는 페이지에 바로 표시됩니다

리포트가 그려지면 발화한 지문의 위치가 **페이지 위에 색 테두리와 라벨로 즉시 표시**됩니다 (기본 켬, 헤더의 "표시" 버튼으로 끔).
색은 카테고리를 따릅니다 — 🧟 빨강, 🎨 보라, 🧱 호박, 🔧 청록. 한 요소에 여러 지문이 겹치면 가중치가 높은 것 하나만 라벨로 붙습니다.
행의 "이 항목만 N곳 표시"를 누르면 그 지문만 남고, 헤더에 "전체 표시" 복귀 버튼이 뜹니다.

오버레이는 페이지 요소에 클래스를 붙이지 않고 **별도 고정 레이어에 상자를 그립니다.** 페이지 CSS와 충돌하지 않고,
`img`·`svg` 같은 `::after` 불가 요소에도 라벨이 붙고, 스캔 대상에서 스스로를 제외합니다.

**표시할 요소가 없는 지문은 두 종류뿐입니다.** `<title>`·meta·파비콘·전역 폰트처럼 애초에 요소가 아닌 **페이지 전체 속성**(`scope: 'page'`)은
"페이지 전체 속성" 칩으로 구분됩니다. 값 남발·팔레트·플레이스홀더 같은 나머지는 전부 요소를 짚습니다 —
값 남발은 "한두 곳에서만 쓰인 별종 값"을 가진 요소를, 팔레트는 Tailwind 기본색을 쓴 요소를 표시합니다.

### 🫗 취향 규칙 (taste) — 3종, 점수에 반영 안 함

eyebrow 레이블(`INTERFACE INVENTORY · 2026`), 대제목 끝 마침표(`Small parts. Clear systems.`), 다크모드 토글.

**이걸 분리한 이유:** 셋 다 사람도 자주 쓰는 정상적인 디자인 선택입니다.
Basecamp의 `"Tell me if this sounds about right."`은 1999년부터 써온 그들의 말투지 AI 흉내가 아닙니다.
취향 규칙을 점수에 섞으면 **거슬리는 걸 추가할수록 슬롭 점수가 오르는 모순**이 생깁니다.
그래서 패널에서 별도 섹션으로 빠지고, 하이라이트로 한 번에 찾아 지울 수만 있게 했습니다.

시그널에 `kind: 'taste'` 를 달면 점수에서 빠집니다. 기본값은 `'tell'`.

점수 = 발화 시그널 가중치 합 / 전체 가중치 합 × 100.
'tell' 시그널만 합산합니다. `0–14 깨끗함 · 15–29 약간 티남 · 30–49 티남 · 50+ 많이 티남`

슬롭으로 잡히면 안 됩니다 — 오탐을 막아주는 가장 값진 테스트 세트예요.

### 패널 UI 프리뷰 — `test/panel-preview.html`

익스텐션을 크롬에 로드하지 않고 사이드패널 UI를 실제 리포트로 렌더합니다.
`chrome.*` API를 심(shim)으로 대체하고, iframe에 대상 페이지를 띄워 실제 엔진으로 채점한 뒤
그 리포트를 진짜 `panel.js`에 먹입니다. 상단 드롭다운으로 대상을 바꿉니다.

프리뷰에서는 확장 API를 모의 실행합니다. 실제 권한 확인창이나 툴바 단축키 동작은 별도 확인이 필요합니다.

### 크롬 로드 전 확인된 것

- `manifest.json`이 크롬 자체 검증기(`--pack-extension`)를 통과합니다.
  초기 버전에 `default_locale: "ko"`가 `_locales/` 없이 들어가 있어 **로드가 거부되는 상태**였고, 제거했습니다.
- 사용하는 `chrome.*` API 9종이 선언된 권한 4종(`activeTab`·`scripting`·`sidePanel`·`storage`)으로 전부 커버됩니다.
- 패널에 인라인 스크립트·인라인 핸들러가 없어 MV3 CSP에 걸리지 않습니다.
- **사이드패널이 안 열리는 함정을 고쳤습니다.** `chrome.sidePanel.open()`은 사용자 제스처 컨텍스트 안에서만
  허용되는데, 그 앞에서 `tabs.query`·`storage.set`을 `await` 하면 컨텍스트가 사라져 조용히 실패합니다.
  워커는 이제 아무것도 기다리지 않고 패널을 먼저 열고, 패널이 스스로 활성 탭을 찾는 폴백을 갖습니다.
- **도움말·진단 정보.** 하단을 펼치면 `탭 12 · 창 3 · updated(12) complete`처럼 마지막 이벤트와 에러를 확인할 수 있습니다.
  동작이 이상하면 이 줄을 복사해 원인을 좁힐 수 있습니다.
- **디버깅:** 반응이 없으면 `chrome://extensions` → 밤티 카드의 **"서비스 워커"** 링크를 눌러 콘솔을 보세요.
  `[밤티]` 접두어로 에러가 찍힙니다.
- **아직 못 한 것:** 실제 크롬에서 단축키 → 사이드패널 열림 → 주입 → 스캔 흐름의 실기 확인. 이건 로드해야만 됩니다.
  2026-09-05 별도 Chromium 프로필에서 확장 로드와 실제 권한 부족 화면은 확인했습니다(JS 오류 0).
  툴바·단축키로 여는 네이티브 사이드패널의 전체 흐름은 수동 확인이 필요합니다.

### 값 남발 시그널은 이렇게 찾았습니다

가설 두 개가 먼저 틀렸고, 그 실패가 방법을 고쳤습니다.

1. **소스 흉터 가설 (기각)** — `!important`·벤더 프리픽스·TODO 수로 사람/AI를 가르려 했으나,
   AI 후보는 비압축 손코드고 대조군은 미니파이된 프로덕션 번들이라 **비교 자체가 무효**였습니다.
   주석·포맷·프리픽스는 저자가 아니라 빌드 파이프라인의 산물입니다.
2. **미디어쿼리 밀도 가설 (기각)** — AI 0~9개 vs 사람 51~305개로 10~100배 차이가 실재하지만,
   미디어쿼리 0개인 `kimi3`가 375px에서 멀쩡히 렌더됩니다. flexbox/grid의 내재적 반응형으로 충분해서
   **차이는 있으나 결함이 아닙니다.** 🧟 카테고리에 넣었으면 오탐이 됐습니다.
3. **성공한 방법** — 가설을 세우는 대신 특징을 전부 뽑아 분리도를 자동 계산 (`test/signature.html`).
   그리고 대조군을 마케팅 사이트에서 **사람이 만든 디자인시스템 문서**로 교체해 장르를 통제했습니다.

남은 교란: AI 표본 7개가 전부 한 세션의 컴포넌트 갤러리고, 사람 표본은 성숙한 디자인시스템입니다.
그래서 이 시그널이 실제로 재는 건 "AI가 썼다"가 아니라 **"디자인 시스템 규율이 없다"** 에 가깝습니다.
개선 도구로서는 오히려 이쪽이 더 쓸모 있습니다 — 근거가 구체적이고 바로 고칠 수 있으니까요.

### 알려진 한계

- 음성 대조군이 12곳입니다(AI 후보 7 + 사람 5). 배포 전 사람 표본을 20곳 이상으로 늘려야 합니다.
- `asset/gpt_sol_5.6`은 생성 시 스킬이 앞단에 붙어 순수 모델 출력이 아닙니다. 모델별 비교에선 제외하세요.
- `purple-blue-gradient`는 Stripe처럼 보라-파랑을 **브랜드 색으로 정당하게 쓰는** 사이트에서도 발화합니다.
  점수 합산에서 희석되도록 설계했지만, 단일 시그널만 보고 판단하면 안 되는 이유입니다.
- 미러링 테스트는 JS 렌더링 콘텐츠를 잡지 못합니다. 실제 익스텐션은 라이브 DOM을 보므로 해당 없음.
- 테스트 하네스는 페이지 CSP에 막힙니다(그래서 미러링). **익스텐션 본체는 isolated world라 무관합니다.**

## 시그널 추가하기

`src/core/signals.js` 의 배열에 하나 더 넣으면 끝입니다. 등록 절차 없음.

```js
{
  id: 'my-signal', cat: 'visual', weight: 6,
  label: '사람이 읽을 이름',
  hint: '어떻게 고쳐야 하는지 — 한 문장으로, 구체적으로',
  detect(ctx) {
    const hit = ctx.els.filter(el => /* ... */);
    return hit.length ? { ev: `근거 ${hit.length}건`, nodes: hit } : null;
  }
}
```

`nodes`를 반환하면 패널에서 "페이지에서 N곳 표시" 버튼이 활성화됩니다.

사람도 정상적으로 쓰는 디자인 선택이라면 `kind: 'taste'` 를 붙이세요.
점수에서 빠지고 별도 섹션으로 나갑니다 — 이게 오탐으로 신뢰를 잃지 않는 방법입니다.
